# ADR 001. Хранение заметок в памяти процесса

**Статус:** Принято
**Дата:** 2026-09-20
**Участники:** вся команда

## Контекст

Сервис нужен как учебный объект: на нём команда отрабатывает работу
с репозиторием, Pull Request и инструменты анализа кода. Заметки не имеют
ценности, после перезапуска их никто не ищет. На старте у команды не было
времени настраивать базу, а у части участников нет Docker.

## Рассмотренные варианты

1. **Словарь в памяти процесса.** Ноль зависимостей, запуск одной командой.
2. **SQLite-файл рядом с приложением.** Данные переживают перезапуск,
   но появляются миграции и файл, который легко случайно закоммитить.
3. **PostgreSQL в контейнере.** Как в настоящем проекте, но нужен Docker
   у каждого участника и отдельная настройка подключения.

## Решение

Выбран вариант 1: заметки лежат в словаре `notes` в модуле `main.py`,
ключ — целое число. Вариант 3 откладываем, пока Docker есть не у всех.

## Последствия

Плюсы:
- запуск без внешних сервисов, тестам не нужна база;
- код хранения занимает несколько строк, его легко читать.

Минусы:
- все заметки теряются при перезапуске сервера;
- нельзя запускать несколько процессов: у каждого будет свой словарь;
- номер новой заметки — наибольший существующий плюс один: если удалить
  заметку с наибольшим номером, этот номер получит следующая созданная,
  и клиент, сохранивший старый номер, удалит чужую заметку;
- при переходе на базу придётся заменить словарь слоем доступа
  к данным во всех обработчиках.

## Когда пересмотреть

- Заметки понадобятся после перезапуска.
- В проекте появится Docker Compose с базой данных.
- Сервис начнут запускать с несколькими воркерами.
