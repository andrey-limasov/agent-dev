# Программа курса: Мульти-агентная разработка приложений

**Объем:** 108 часов (16 ак. ч. лекций-семинаров, 32 ак. ч. практик, 60 ч. СРС)  
**Формат:** 16 недель (1 семестр), синхронизация по неделям с курсом "Управление конфигурацией бизнес-приложений": мульти-агентная система курса — помощник команды разработчиков бэкенда, который команда строит в этом курсе. Помощник живёт в отдельном репозитории и работает с тем состоянием бэкенда, которое есть у команды на этой неделе.  
**Расписание:** 
- **Нечётная неделя:** 1 пара (2 академических часа = 90 минут) — Лекция-семинар (обсуждение, проектирование, презентации, рефлексия). **Без кодинга.**
- **Чётная неделя:** 2 пары (4 академических часа = 180 минут) — Практикум (Pair Programming, реализация, интеграция, peer review кода).

---

## Детальный план занятий (8 двухнедельных циклов)

### Цикл 1: Введение и старт (Недели 1-2)
*Синхронизация: Формирование команд и инициализация репозитория в курсе "Конфигурирование".*
- **Неделя 1 (нечётная) | Лекция 1 (2 ак. ч. / 90 мин):** Введение в AI-агентов. От LLM к автономным агентам. Паттерны: ReAct, Reflection. Обзор стека (CrewAI, LangChain, Qwen). **Формат:** PBL-обсуждение инженерной проблемы, командное проектирование первого Tool помощника над кодом бэкенда, презентации идей, рефлексия.
- **Неделя 2 (чётная) | Практика 1 (4 ак. ч. / 180 мин):** Pair Programming. Отдельный репозиторий помощника и настройка окружения (Ollama / облачный OpenAI-совместимый провайдер). Реализация спроектированного Tool над кодом бэкенда (только чтение). Настройка `pydantic-settings` для переключения между моделями и пути к репозиторию бэкенда. Peer review кода и написание первого ADR. Если у команды ещё нет бэкенда «Конфигурирования», Tool пишется над учебным бэкендом `templates/sample-backend/`, а потом путь к бэкенду меняется одной строкой `.env`.

### Цикл 2: Инструменты агентов (Tool Use) (Недели 3-4)
*Синхронизация: стратегии ветвления, branch protection и PR-процесс, ADR 001 в курсе "Конфигурирование".*
- **Неделя 3 (нечётная) | Лекция 2 (2 ак. ч. / 90 мин):** Function calling. Как научить агента действовать, а не только говорить. Создание инструментов для работы с кодом: аналоги LSP/ctags (`search_codebase`, `read_file`, `run_linter`). **Формат:** Анализ паттернов безопасного выполнения кода, проектирование инструментов для анализа собственного проекта.
- **Неделя 4 (чётная) | Практика 2 (4 ак. ч. / 180 мин):** Разработка кастомных Tools для анализа кода. Интеграция агента с файловой структурой бэкенда. Отладка обработки ошибок, чтобы агент не "падал" при неверном выводе линтера.

### Цикл 3: RAG и работа со знаниями (Недели 5-6)
*Синхронизация: Docker, менеджер зависимостей и Docker Compose (FastAPI + PostgreSQL) в курсе "Конфигурирование".*
- **Неделя 5 (нечётная) | Лекция 3 (2 ак. ч. / 90 мин):** Управление памятью и контекстом. Краткосрочная vs долгосрочная память. Введение в RAG (Retrieval-Augmented Generation). Стратегии чанкинга и эмбеддинга технической документации. **Формат:** Командное проектирование схемы RAG-пайплайна для документации своего проекта, оценка различных стратегий чанкинга.
- **Неделя 6 (чётная) | Практика 3 (4 ак. ч. / 180 мин):** Основы RAG. Создание векторного хранилища (ChromaDB в репозитории помощника; альтернатива — pgvector в собственном контейнере помощника, не в БД бэкенда). Загрузка документации проекта, реализация семантического поиска и интеграция его как Tool для агента.

### Цикл 4: Мульти-агентная оркестрация (Недели 7-8)
*Синхронизация: 12-Factor App, `pydantic-settings`, секреты и pre-commit в курсе "Конфигурирование".*
- **Неделя 7 (нечётная) | Лекция 4 (2 ак. ч. / 90 мин):** Паттерны оркестрации: Sequential, Hierarchical, Collaborative. Роль Manager-агента. Распределение ролей в команде разработчиков-агентов (например: Исследователь → Кодер → Ревьюер). **Формат:** Проектирование архитектуры мульти-агентной системы для своей задачи, защита архитектуры перед группой.
- **Неделя 8 (чётная) | Практика 4 (4 ак. ч. / 180 мин):** Создание первой Crew из 2-3 агентов. Отладка передачи контекста между агентами. Реализация цикла "генерация кода → проверка линтером (через Tool) → исправление".

### Цикл 5: Помощник и API бэкенда: контракты и Structured Output (Недели 9-10)
*Синхронизация: философия CI/CD и первый workflow с линтером и статическим анализом на PR в курсе "Конфигурирование"; тесты в CI появятся там на неделях 11-12.*
- **Неделя 9 (нечётная) | Лекция 5 (2 ак. ч. / 90 мин):** Помощник и внешний мир. Контракт API бэкенда (OpenAPI-схема FastAPI) как источник истины для агента вместо догадок модели. Вызовы REST API из агентов: таймауты, обработка ошибок сети, асинхронные задачи. Structured Output через Pydantic для гарантированного формата результата помощника. **Формат:** Анализ кейсов, проектирование Pydantic-контракта результата помощника (тест-кейсы, отчёт) и правил доступа к репозиторию бэкенда: чтение — да, изменения — только через Pull Request, который принимают люди.
- **Неделя 10 (чётная) | Практика 5 (4 ак. ч. / 180 мин):** Помощник получает OpenAPI-схему работающего бэкенда (локальный стенд Docker Compose из курса "Конфигурирование") и генерирует pytest-тесты к эндпоинтам в виде Pydantic-структуры. Валидация результата и проверка сгенерированного кода линтером через Tool, обработка ошибок сети, таймауты и retry-логика. Запуск сценария одной командой из репозитория помощника (CLI); сгенерированные тесты запускаются pytest'ом в репозитории помощника — в бэкенде pytest появится на неделе 11.

### Цикл 6: Надёжность, Guardrails и Тестирование (Недели 11-12)
*Синхронизация: тесты (pytest) и сборка в CI, публикация Docker-образа в реестр в курсе "Конфигурирование".*
- **Неделя 11 (нечётная) | Лекция 6 (2 ак. ч. / 90 мин):** Надёжность и Guardrails. Обработка галлюцинаций. Тестирование недетерминированных систем: стратегии мокирования LLM (запрет реальных вызовов в CI/CD). **Формат:** Разбор стратегий тестирования, проектирование mock-объектов для своих агентов.
- **Неделя 12 (чётная) | Практика 6 (4 ак. ч. / 180 мин):** Реализация Retry-логики и fallback-сценариев. Написание `pytest`-тестов для Crew с использованием фикстур, возвращающих предопределенные JSON-ответы (мокирование). Обеспечение зелёного пайплайна репозитория помощника. Лучшие тесты, сгенерированные помощником, команда предлагает в репозиторий бэкенда обычным Pull Request — их проверяет CI бэкенда (тесты в CI «Конфигурирования» — недели 11–12).

### Цикл 7: Observability и Оптимизация (Недели 13-14)
*Синхронизация: Деплой на VPS, reverse-proxy и мониторинг в курсе "Конфигурирование".*
- **Неделя 13 (нечётная) | Лекция 7 (2 ак. ч. / 90 мин):** Observability для агентов. Логирование ReAct-трасс (Thought, Action, Observation). Оптимизация затрат: кэширование ответов, роутинг запросов к разным моделям в зависимости от сложности задачи. **Формат:** Аудит собственных лог-файлов, проектирование дашборда или структуры логов для отладки.
- **Неделя 14 (чётная) | Практика 7 (4 ак. ч. / 180 мин):** Настройка структурированного логирования шагов агента (например, через LangFuse или кастомные JSON-логи). Реализация простого кэша для RAG-запросов. Аудит безопасности (защита от Prompt Injection).

### Цикл 8: Финальная интеграция и Защита (Недели 15-16)
*Синхронизация: Финальная сборка, документация и подготовка к защите в курсе "Конфигурирование".*
- **Неделя 15 (нечётная) | Лекция 8 (2 ак. ч. / 90 мин):** Финальная интеграция помощника в процесс разработки команды. Питчинг и демонстрация недетерминированных систем: как показать работающее демо со сценариями fallback. **Формат:** Генеральная репетиция защиты, peer-review презентаций команд.
- **Неделя 16 (чётная) | Практика 8 (4 ак. ч. / 180 мин):** **Защита проектов.** Live-demo, проверка DoD обоих курсов (бэкенд — по DoD "Конфигурирования", помощник — по DoD мульти-агентной разработки), ответы на вопросы, оценка 360° (50% преподаватель, 25% другие команды, 25% сокомандники).

## Методические указания для СРС (60 часов)

Самостоятельная работа не является "домашним заданием" в классическом понимании. Это время, выделенное на:
1. **Изучение документации:** Официальные гайды CrewAI, LangChain, Ollama, выбранного облачного провайдера.
2. **Эксперименты с промптами:** Подбор оптимальных `backstory` и `goal` для агентов своего проекта, итеративное улучшение.
3. **Написание тестов:** Создание надежных моков для LLM-вызовов, чтобы гарантировать прохождение CI/CD.
4. **Командная синхронизация:** Встречи с участниками, отвечающими за "Конфигурирование", чтобы помощник опирался на актуальный код, контракты API и правила репозитория бэкенда. Изменения в бэкенд — только через Pull Request.

## Важные правила курса

1. **Запрет на кодинг на лекциях:** Лекции предназначены для анализа, проектирования, презентаций и рефлексии. Весь код пишется на практикумах. Это обеспечивает фокус на задачах высокого порядка по таксономии Блума.
2. **Запрет на реальные вызовы LLM в CI/CD:** Все тесты в пайплайне должны использовать моки. Реальные вызовы разрешены только при локальной разработке и финальном демо. Это касается CI репозитория помощника и любого кода, который помощник предлагает в репозиторий бэкенда.
3. **Инженерная честность:** Если агент не справляется с задачей стабильно, честнее реализовать fallback на жесткую логику, упростить задачу или использовать Human-in-the-loop, чем демонстрировать "хрупкую магию".
4. **Совместная ответственность:** Выпускной проект общий для двух курсов, и команда отвечает за оба своих репозитория: за работоспособность бэкенда (DoD конфигурирования) и за помощника (DoD мульти-агентной разработки). Помощник не правит бэкенд напрямую: он читает и анализирует код, а изменения предлагает через Pull Request, который принимают люди.
5. **Безопасность инструментов:** Агенты не должны иметь прав на выполнение произвольных shell-команд (`os.system`) без строгих ограничений и песочницы.
