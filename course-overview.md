# Курс: Мульти-агентная разработка приложений

**Формат:** Проектный интенсив для 4 курса  
**Объем:** 108 часов (16 ч. лекций-воркшопов, 32 ч. практик, 60 ч. СРС)  
**Стек:** Python 3.11–3.13 (CrewAI не поддерживает 3.14), CrewAI / LangChain, Ollama (локально) + облачный OpenAI-совместимый провайдер (OpenRouter, Yandex AI Studio), ChromaDB / pgvector, Pytest (mock LLM)  
**Статус:** Базовые требования (связаны с курсом "Управление конфигурацией бизнес-приложений": мульти-агентная система — помощник команды бэкенда этого курса)

---

## 🎯 Цели курса

1. **Образовательная:** Сформировать практические навыки проектирования, разработки и отладки мульти-агентных систем на базе больших языковых моделей (LLM).
2. **Инженерная:** Научить создавать надежных AI-агентов, использующих инструменты (Tools), память (Memory) и Retrieval-Augmented Generation (RAG) для решения реальных бизнес-задач.
3. **Интеграционная:** Отработать навыки совместной разработки, где мульти-агентный помощник встраивается в процесс разработки (Pull Request, CI) команды, которая строит клиент-серверное приложение с полноценной инфраструктурой (CI/CD, Docker, мониторинг), и не нарушает владения кодом: изменения в бэкенд вносят люди через Pull Request.
4. **Этическая и безопасная:** Понимать ограничения LLM, внедрять guardrails и обеспечивать предсказуемость поведения агентов.

---

## 🤝 Связь с курсом "Конфигурирование приложений"

Оба курса работают над **одним выпускным проектом** в одних и тех же командах (3–4 человека). В "Конфигурировании" команда строит бэкенд, здесь — мульти-агентного помощника для разработчиков этого бэкенда: генерация кода и тестов, ревью, анализ кода. Помощник живёт в отдельном репозитории команды (свой venv, `.env`, зависимости, CI).

| Аспект | Курс "Конфигурирование" | Курс "Мульти-агентная разработка" |
| :--- | :--- | :--- |
| **Фокус** | Инфраструктура, надежность, поставка | Помощник разработчиков: интеллект, автоматизация инженерных задач |
| **Репозиторий** | Бэкенд: FastAPI, PostgreSQL, Docker, CI/CD, деплой, мониторинг | Помощник: оркестрация агентов, RAG, Tool Use, промпт-инжиниринг, AI-тестирование, свой CI (только моки LLM) |
| **Объект работы** | Бизнес-приложение для пользователей | Репозиторий бэкенда: код, OpenAPI-схема, PR-процесс — только чтение |
| **Результат** | Работающее приложение по DoD курса | Тесты, замечания ревью, отчёты анализа; в бэкенд они попадают Pull Request, который делают и принимают люди. Запуск — командой из репозитория помощника (CLI) и job в CI |

**Пример синергии:** Команда разрабатывает бэкенд системы Help Desk. "Конфигурирование" обеспечивает API тикетов, локальный стенд Docker Compose и пайплайн тестов. "Мульти-агенты" создают Crew помощника из трёх агентов: *Исследователь* (находит в коде бэкенда нужные эндпоинты и модели, ищет по документации и ADR через RAG), *Кодер* (генерирует pytest-тесты к эндпоинтам тикетов по OpenAPI-схеме и проверяет их линтером через Tool) и *Ревьюер* (проверяет результат и готовит описание Pull Request). Тесты в бэкенд вносит человек обычным Pull Request.

## 🧠 Педагогические принципы

- **Flipped Classroom (Перевернутый класс):** Теория (паттерны агентов, документация фреймворков) изучается самостоятельно. Воркшопы посвящены разбору сложных кейсов, код-ревью и парному программированию.
- **Project-Based Learning (PBL):** Все практические задания напрямую строят итоговый выпускной проект. Нет "академических" задач, оторванных от реальности.
- **Инженерная честность:** Акцент на том, что LLM — это недетерминированный компонент. Студенты учатся писать тесты с моками, обрабатывать галлюцинации и внедрять fallback-механизмы.
- **AI-Assisted Development:** Студенты поощряются использовать AI-агенты (включая Qwen Code) для ускорения своей работы, но обязаны понимать и контролировать каждый сгенерированный фрагмент кода.

## 🛠️ Технологический стек

| Компонент | Технология | Обоснование |
| :--- | :--- | :--- |
| **Язык** | Python 3.11–3.13 (CrewAI не поддерживает 3.14) | Единый стек с курсом конфигурирования, отличная поддержка AI-библиотек. |
| **Оркестрация** | CrewAI (основной) + LangChain (для Tools/RAG) | CrewAI предоставляет интуитивную абстракцию ролей (Agent, Task, Crew), идеальную для новичков. LangChain дает гибкость для создания кастомных инструментов. |
| **Модели (LLM)** | Облачный OpenAI-совместимый провайдер + Ollama (локально, Qwen3:4b-instruct — модель с tools) | Баланс между качеством (облако) и приватностью/бесплатностью (локально). Студенты учатся абстрагировать провайдера. |
| **Память / RAG** | ChromaDB (основная) или pgvector | ChromaDB — легковесное локальное хранилище в репозитории помощника, без внешних сервисов; pgvector — альтернатива только в собственном контейнере помощника, не в БД бэкенда. |
| **Инструменты агентов** | Кастомные Python-функции + File System Tools + LSP-like checkers (`ruff`, `mypy`) | Агенты должны уметь не только "болтать", но и проверять свой код, читать файлы проекта. |
| **Тестирование** | Pytest + `langchain-mock` / кастомные фикстуры | Обязательное мокирование ответов LLM для детерминированного CI/CD. |
| **Observability** | LangFuse (open-source) или структурированное логирование трасс (ReAct traces) | Для отладки цепочек рассуждений агентов. |

## 📊 Оценивание (360°)

Аналогично курсу "Конфигурирование", оценка складывается из трех компонентов. Где она выставляется — `syllabus.md`, неделя 16 (защита проектов).

- **50%** – оценка преподавателя (архитектура агентов, качество промптов, реализация Tools, RAG, тестирование, интеграция, документация, защита).
- **25%** – оценка других команд (воспроизводимость AI-сценариев, качество документации, стабильность работы агентов на демо).
- **25%** – оценка сокомандников (вклад в разработку агентов, качество code review, надежность, инициативность), формирующая индивидуальный коэффициент $K_{вклада}$ (0.5 – 1.2).

## 🚀 Ожидаемые результаты к концу курса

К концу семестра каждый студент должен уметь:
1. Спроектировать мульти-агентную систему под конкретную задачу команды разработки, выбрав правильный паттерн оркестрации.
2. Реализовать кастомные Tools для агентов, включая безопасную работу с файловой системой и внешними API.
3. Построить и оценить RAG-пайплайн для предоставления агентам актуального контекста.
4. Написать детерминированные тесты для недетерминированных AI-компонентов.
5. Встроить помощника в процесс разработки команды (CLI, CI, Pull Request), не нарушая владения кодом бэкенда и соблюдая принципы 12-Factor App и безопасности.
6. Обосновать архитектурные решения в формате ADR.
