### 1. Входной билет: схема своего стенда (15 мин)

Вы поднимете стенд бэкенда из курса «Конфигурирование», сохраните его схему в файл рядом с репозиториями и остановите стенд. В бэкенде ничего не меняется. Для билета подойдёт любой ноутбук команды с работающим Docker, но лучше сразу тот, где запускается Crew помощника: на практике 5 стенд понадобится там.

**Учебный бэкенд «Заметки»:** стенда Docker Compose у него нет. Пропустите шаги 1–4, в шаге 6 напишите в чат строку «Заметки». На воркшопе возьмёте [схему и код из этого файла](#заметки). К практике 5 учебный бэкенд запускается по его `README.md`, подробности будут на практике 5.

1. Перейдите в корень бэкенда (`<проект>` — каталог из `AI_REPO_ROOT` в `.env` помощника) и поднимите стенд. Команды одинаковы в PowerShell и Git Bash:
   ```
   cd ../<проект>
   docker compose up -d --build
   docker compose ps
   ```
   Ожидаемый вывод `docker compose ps` — строка приложения и строка базы данных со статусом `Up`, у приложения в столбце `PORTS` есть `->8000`:
   ```
   NAME             IMAGE            ...   SERVICE   STATUS                            PORTS
   <проект>-app-1   <проект>-app     ...   app       Up 3 seconds (health: starting)   0.0.0.0:8000->8000/tcp, [::]:8000->8000/tcp
   <проект>-db-1    postgres:16      ...   db        Up 12 seconds (healthy)           0.0.0.0:5432->5432/tcp, [::]:5432->5432/tcp
   ```
   Первая сборка образа занимает несколько минут. `health: starting` сразу после запуска — норма: примерно через 15 секунд там будет `healthy`.

   **Если не получилось:**
   - `failed to connect to the docker API` — не запущен Docker Desktop. Запустите его и повторите команду.
   - Linux: `permission denied while trying to connect to the docker API` (Docker 29 и новее) или `permission denied while trying to connect to the Docker daemon socket` (старые версии) — Docker у вас работает только через `sudo`. Сейчас пишите `sudo` перед каждой командой `docker` в шагах 1 и 4: `sudo docker compose up -d --build`. Насовсем — `sudo usermod -aG docker $USER`, затем выйти из системы и войти снова: [Docker Docs, Linux post-installation steps](https://docs.docker.com/engine/install/linux-postinstall/), раздел *Manage Docker as a non-root user*, 2 минуты.
   - `required variable POSTGRES_PASSWORD is missing a value` — в корне бэкенда нет файла `.env`. Скопируйте `.env.example` в `.env` и задайте пароль: `.env` — ваша локальная настройка, в git он не попадает.
   - `port is already allocated`, `ports are not available` или, на Linux, `address already in use` — порт занят, его номер есть в сообщении. Порт `8000`: поменяйте `APP_PORT` в `.env` на свободный, например `8001`, повторите `docker compose up -d`, а в шагах 2 и 4 подставьте этот порт вместо `8000`. Порт `5432`: остановите другой стенд или локальный PostgreSQL.
   - Ошибки нет, но у приложения в `PORTS` нет `->8000`, например только `8000/tcp` — порт приложения не опубликован, и на `localhost:8000` отвечает не оно. Выполните `docker compose down`, закройте другой процесс на этом порту, часто это забытый `uvicorn`, и повторите `docker compose up -d`. Не помогло — поступите, как при занятом порте `8000`.
   - Прошло 10 минут, стенд не поднялся — не чините его сейчас. Выполните `docker compose down` и в шаге 6 напишите в чат «стенд:» и последнюю строку ошибки. На воркшопе возьмёте [схему из этого файла](#бэкенд-недели-8) и код своего бэкенда, а стенд доведёте до работы до практики 5 на машине, где запускается Crew: это пункт домашнего задания.

2. Сохраните схему. Команда отличается: в Windows PowerShell слово `curl` означает другую команду, поэтому там нужно `curl.exe`.

   Git Bash, macOS, Linux:
   ```bash
   curl -fsS http://localhost:8000/openapi.json -o ../openapi-backend.json
   ```
   Windows PowerShell:
   ```powershell
   curl.exe -fsS http://localhost:8000/openapi.json -o ../openapi-backend.json
   ```
   При успехе команда ничего не печатает.

   **Если не получилось:**
   - `curl: (22) The requested URL returned error: 404` — приложение работает, а схема отключена: обычно `APP_ENV=prod`. Проверьте, что приложение живо: тот же запрос к `/health` или `/version` отвечает. В `.env` поставьте `APP_ENV=dev`, выполните `docker compose up -d` и повторите команду через 10 секунд. Файл `.env` не в git, бэкенд от этого не меняется.
   - `curl: (7) Failed to connect to localhost` — приложение не запущено или порт другой: посмотрите столбец `PORTS` в `docker compose ps`.
   - `curl: (52) Empty reply from server` или `curl: (56)` — приложение ещё запускается: подождите 10 секунд и повторите.

3. Проверьте файл. Команда одинакова в PowerShell и Git Bash:
   ```
   python -c "import json; d=json.load(open('../openapi-backend.json', encoding='utf-8')); print(sorted(d['paths']))"
   ```
   Ожидаемый вывод — список ваших путей, например:
   ```
   ['/', '/health', '/version']
   ```
   Сравните список с эндпоинтами в коде бэкенда: пути должны совпасть. Чужие пути, например `/notes` у своего бэкенда, значат, что ответил другой сервер: выполните проверку шага 4 сейчас. На macOS и Linux в этой и следующей командах вместо `python` пишите `python3`.

   Разбить файл на строки для чтения можно командой `python -m json.tool --no-ensure-ascii ../openapi-backend.json`.

4. Остановите стенд. Данные базы остаются, ключ `-v` не добавляйте:
   ```
   docker compose down
   docker compose ps
   ```
   Ожидаемый вывод `docker compose down` — строки `Container ... Removed` и `Network ... Removed`, `docker compose ps` — только заголовок таблицы.

   Проверьте, что схему отдал ваш стенд: он остановлен, значит, порт должен молчать. Запрос тот же, что в шаге 2, но без файла.

   Git Bash, macOS, Linux:
   ```bash
   curl -fsS http://localhost:8000/openapi.json
   ```
   Windows PowerShell:
   ```powershell
   curl.exe -fsS http://localhost:8000/openapi.json
   ```
   Ожидаемый вывод — ошибка `curl`, обычно `curl: (7) Failed to connect to localhost`. Текст ошибки не важен: важно, что JSON не напечатан.

   **Если не получилось:** команда напечатала JSON — на порту работает другой процесс, и файл схемы мог прийти от него. Удалите `../openapi-backend.json`, закройте этот процесс, часто это забытый `uvicorn`, или поставьте в `.env` бэкенда `APP_PORT=8001` и подставьте этот порт в команды. Повторите шаги 1–4.

   Вернитесь в репозиторий помощника:
   ```
   cd ../<репозиторий помощника>
   ```

5. Создайте в репозитории помощника файл `docs/result-contract.md` и скопируйте в него [каркас](#каркас-docsresult-contractmd) целиком. **Не коммитьте его в текущую ветку:** ветка `feature/api-contract` появится в домашнем задании воркшопа.
6. До начала пары пришлите в чат курса **сам файл** `openapi-backend.json` (или строку «Заметки», или «стенд: …») и отдельной строкой — ссылку на PR практики 4.

Для команд на «Заметках» и для команд, у которых стенд не поднялся. Настоящие фрагменты: схема получена запуском, код — из репозиториев. Сначала прочитайте только схему и запишите предсказание, код смотрите потом.

### Заметки

Схема, эндпоинт `POST /notes` (FastAPI 0.162, `openapi.json`, фрагмент):

```json
"/notes": {
  "post": {
    "summary": "Create Note",
    "description": "Создать заметку.",
    "operationId": "create_note_notes_post",
    "requestBody": {
      "content": {"application/json": {"schema": {"$ref": "#/components/schemas/NoteIn"}}},
      "required": true
    },
    "responses": {
      "201": {"description": "Successful Response",
              "content": {"application/json": {"schema": {}}}},
      "422": {"description": "Validation Error",
              "content": {"application/json": {"schema": {"$ref": "#/components/schemas/HTTPValidationError"}}}}
    }
  }
}
```

Схема, модель `NoteIn`:

```json
"NoteIn": {
  "properties": {
    "title": {"type": "string", "title": "Title"},
    "text": {"type": "string", "title": "Text", "default": ""}
  },
  "type": "object",
  "required": ["title"],
  "title": "NoteIn"
}
```

Код, `main.py`, строки 28–33:

```python
@app.post("/notes", status_code=201)
async def create_note(note: NoteIn):
    """Создать заметку."""
    note_id = max(notes, default=0) + 1
    notes[note_id] = {"id": note_id, **note.model_dump()}
    return notes[note_id]
```

Эндпоинт `DELETE /notes/{note_id}` на этапе 1 разбирает вся группа, поэтому на «Заметках» в раздел 1 берите `POST /notes`.

## Справка: Structured Output в CrewAI

Сверено с `crewai==1.15.22`, версией курса. Страница [Tasks](https://docs.crewai.com/en/concepts/tasks) описывает новые версии: в конце подраздела *Using `output_json`* — повторный запрос к модели, если итог не подошёл, в разделе *Task Output* — что при неудаче заполнен только `raw`. В `1.15.22` повторного запроса нет, а отказ — исключение. В `1.15.37` на том же ответе исключения нет: итог `ok`, `result.pydantic` равен `None`. При обновлении версии проверка по исключению молча перестанет работать. Опирайтесь на эту таблицу и на установленную версию.

**Как задаётся.** В курсе — поле `output_pydantic` у `Task`: разобранный объект лежит в `result.pydantic`, исходный текст — в `result.raw`. Поле `output_json` даёт словарь в `result.json_dict`, а `result.pydantic` при этом пуст. Один `response_model` у агента с Tool ничего не проверяет: `result.pydantic` равен `None`, ошибки нет. Имён `OutputParser` и `StructuredOutput` у `Task` нет.

**Что происходит с итогом.** Таблица — запуск `kickoff()` с агентом с Tool и `output_pydantic`, ответы модели заданы заранее: это проверка поведения CrewAI. Затем это проверено на `qwen3:4b-instruct` в упрощённом запуске (один агент, линтер-заглушка, 21 запуск): строки 1 и 3 наблюдались, строк 2, 4 и 5 в обычной работе модели не было. Как часто такие ответы модель даёт в вашей Crew, вы замерите на практике 5.

| Что модель вернула в итоге задачи | Что произошло | Вызовов LLM на этот итог |
|---|---|---|
| Верный JSON, в том числе внутри текста или блока ` ```json ` | `result.pydantic` заполнен | 1 |
| `"expected_status": "200"`: число строкой | `result.pydantic` заполнен, значение преобразовано в `200` | 1 |
| JSON с неверным типом (`"двести"`), значением не из списка или без обязательного поля; текст с фрагментом `{…}`, который разобрался как JSON | `kickoff()` выбрасывает `pydantic.ValidationError`, второй попытки нет | 1 |
| Текст без `{…}` или обрезанный JSON, отдельный вызов модели вернул JSON | `result.pydantic` заполнен полями, которых агент в итоге не называл; `result.raw` — исходный текст | 2 |
| То же, отдельные вызовы модели JSON не вернули | `kickoff()` выбрасывает `ConverterError` после трёх попыток | 4 |

**Что из этого следует для контракта:**
- Формат не заставляет модель ответить верно. Он не пропускает дальше то, что не прошло проверку, а отказ становится явным.
- Проверка типа не знает, существует ли файл и есть ли эндпоинт. Это проверяет код или человек.
- Заполненный объект не значит, что агент сказал это сам: в четвёртой строке таблицы поля заполнил отдельный вызов модели.
- `write_generated` работает до конца задачи: при отказе формата файл в `generated/` уже записан и остаётся на диске.
- Каркас `ai/run_crew.py` перехватывает только `TimeoutError`, остальное закончится traceback. Это вы поправите на практике 5.

Все поля обязательны: поле есть всегда, пустое значение — пустая строка или пустой список. Кто ловит нарушение каждого ограничения, решаете вы: заполните столбец «Что при нарушении» и добавьте свои поля.

````markdown
В столбце «Что при нарушении» одно или несколько значений, у каждого сказано, при каком нарушении: **отказ формата** (объекта нет) / **отказ кода** (объект есть, проверка кодом сообщила об отказе) / **заметит человек** (формат и код этого не видят). ## Каркас ADR 005 помощника
````

Черновик — домашнее задание воркшопа, статус «Предложено», файл `docs/adr/005-result-contract.md`. На практике 5 он станет «Принято» с цифрами запуска.

```markdown
# ADR 005: Контракт результата помощника

**Статус:** Предложено
**Дата:** …
**Команда:** <имена>

## Контекст
Схема бэкенда не содержит тел ответов: статус и тело берутся из кода.
Итог Crew — текст: код запуска не может его проверить.

## Рассмотренные варианты
1. Текстовый `expected_output`, как на практике 4.
2. Контракт итога Crew: поля из `docs/result-contract.md`, раздел 2.
3. Контракт итога и передачи Исследователь → Кодер.

## Решение
Вариант …; какие поля сверх минимума; что при нарушении;
доступ к работающему бэкенду — только `GET /openapi.json`.

## Последствия
Что стало проще, что усложнилось, чем платим: возможный лишний вызов LLM,
рост промпта Кодера, отказ вместо текста. Как отказ увидит человек.

## Связь с ADR 004 помощника
ADR 004, «Когда пересмотреть»: появилась OpenAPI-схема. Паттерн не меняется
/ новая строка: …

## Когда пересмотреть
Например: в бэкенде появится `response_model`; появятся примеры OpenAPI
(недели 15–16 «Конфигурирования»); понадобится `GET` к эндпоинтам стенда.
```
