### 1. Входной билет: задача разработчика к своему эндпоинту (25 мин)

Входной билет — начало архитектуры вашей Crew. На воркшопе вы допишете её до конца, на практике 4 — соберёте Crew по ней.

1. В репозитории помощника создайте файл `docs/crew-design.md` и скопируйте в него [каркас](#каркас-docscrew-designmd) целиком.
   **Не коммитьте его в `feature/rag-search`**: у архитектуры своя ветка `feature/crew`, она появится после слияния PR практики 3 (домашнее задание воркшопа). До тех пор файл просто лежит в рабочей папке.
2. Выберите **один существующий эндпоинт** своего бэкенда и одно его поведение, которое стоит закрыть тестом. Список эндпоинтов покажет команда из корня репозитория помощника (одинаково в PowerShell и Git Bash):
   ```
   git -C ../<проект> grep -n -E "@(app|router)\.(get|post|put|patch|delete)\("
   ```
   Ожидаемый вывод — файл, строка и декоратор, например:
   ```
   main.py:18:@app.get("/")
   main.py:24:@app.get("/health")
   main.py:45:@app.get("/version")
   ```
   **Если не получилось:**
   - `fatal: cannot change to '../<проект>'` — подставьте имя каталога бэкенда из `AI_REPO_ROOT` в `.env` помощника.
   - `fatal: not a git repository` — у вас учебный бэкенд: его копия — не git-репозиторий. Добавьте ключ `--no-index`, с ним `git grep` ищет и вне репозитория:
     ```
     git -C ../<проект> grep --no-index -n -E "@(app|router)\.(get|post|put|patch|delete)\(" -- ":(exclude).venv" ":(exclude)venv"
     ```
     Исключения в конце команды не дают искать внутри виртуального окружения «Заметок», если вы его создали: без них в вывод попадут десятки строк из кода FastAPI. На «Заметках» это четыре строки, от `main.py:16:@app.get("/")` до `main.py:36:@app.delete("/notes/{note_id}", status_code=204)`. Те же эндпоинты — в таблице «Эндпоинты» `README.md` «Заметок».
   - Пустой вывод — эндпоинты объявлены иначе (например, через `add_api_route`): найдите их в коде сами или командой `git -C ../<проект> grep -n "def "`.
3. Заполните раздел «1. Задача разработчика» каркаса: как разработчик сказал бы задачу в чате; метод и путь; файл и функция-обработчик; **одно** поведение, которое проверяет тест (запрос → статус и тело ответа); откуда известно, что так и должно быть (строки кода, раздел документа); имя файла результата `generated/test_<кратко>.py`.
   Примеры: «`GET /version` возвращает версию приложения», «`GET /health` при недоступной базе отвечает 503 и `{"status": "unhealthy", ...}`». Выбирайте поведение, которое видно в коде обработчика: OpenAPI-схема бэкенда — тема цикла 5, сейчас помощник её не получает. Не выбирайте поведение, которому нужна работающая база данных: тест будут запускать без неё. И не опирайтесь на ответ `/health` «`DATABASE_URL` не задана»: с недели 8 «Конфигурирования» бэкенд без `DATABASE_URL` не запускается вовсе, и этого ответа в коде не будет.
   **Учебный бэкенд «Заметки»:** `DELETE /notes/{note_id}` → 404 разбирается всей группой на этапе 1. Возьмите другое поведение, например `POST /notes` с `title` → 201 и в ответе поле `id` (видно в коде: `create_note`, строки 28–33 `main.py`). Или `POST /notes` без `title` → 422, но тогда тест проверяет только статус: 422 даёт не код обработчика, а проверка FastAPI по модели `NoteIn` (`title: str`, строка 12), и тела этого ответа нет ни в коде, ни в README. Источник — модель `NoteIn` и строка таблицы «Эндпоинты» README.
4. До начала пары пришлите в чат курса **сам файл** `docs/crew-design.md` (не ссылку: он ещё не закоммичен) и отдельной строкой — ссылку на PR практики 3.

## Справка: паттерны в CrewAI

Факты — из документации по ссылкам выше и из установленного `crewai==1.15.22` (версия практики 1). Где они расходятся, сказано явно.

| Паттерн | Как задаётся в CrewAI | Кто решает порядок и исполнителя | Вызовы LLM сверх работы агентов | Что видит следующий исполнитель | В курсе |
|---|---|---|---|---|---|
| **Sequential** | `Crew(..., process=Process.sequential)` — значение по умолчанию | Код: порядок списка `tasks`, у каждой задачи свой `agent` | Нет | Итоговые ответы прошлых задач (`Task.context`), не ответы их Tools | Обязателен на практике 4 |
| **Hierarchical** | `process=Process.hierarchical` и `manager_llm` или `manager_agent`; без них при создании `Crew` — ``1 validation error for Crew`` с текстом ``Attribute `manager_llm` or `manager_agent` is required when using hierarchical process.`` | Порядок задач — код (список `tasks`); кому поручить каждую и сколько раз переспросить — Manager-агент, на ходу. У задачи задан `agent` — Manager поручает только ему | На каждую задачу — поручение (одно или несколько) и итог Manager; возврат на доработку — ещё поручение | Только текст поручения Manager | По желанию на практике 4, после работающего Sequential; на `qwen3:4b-instruct` курсом не проверялся |
| **Collaborative** (делегирование) | `Agent(..., allow_delegation=True)`; по умолчанию `False`. Отдельного процесса нет: в `crewai==1.15.22` у `Process` только `sequential` и `hierarchical` | Агенты сами, по ходу задачи | Каждый вопрос коллеге и каждый ответ коллеги — вызовы; сколько их будет — заранее неизвестно | Коллега видит только вопрос или поручение | Обсуждается на воркшопе; паттерн проекта по Definition of Done — Sequential или Hierarchical |

**Подробности, которые понадобятся в `crew-design.md`:**

- **`Task.context`.** Не задан — в Sequential задача получает итоги **всех** предыдущих задач, склеенные подряд. Список задач — только их итоги. Пустой список `[]` — ничего. Ответы Tools прошлого агента (найденные строки, текст файла) в итог не входят: в итоге только то, что агент написал в финальном ответе по `expected_output`.
- **Manager-агент.** `manager_llm` — CrewAI сам создаёт Manager с этой моделью. `manager_agent` — свой агент с `role`, `goal`, `backstory`; его **нет** в списке `agents`, Tools у него быть не должно: при `kickoff()` CrewAI выдаёт ошибку `Manager agent should not have tools`, а если Manager попал в список `agents`, то уже при создании `Crew` — `1 validation error for Crew` с текстом `Manager agent should not be included in agents list.` Поручение коллеге — Tool `Delegate work to coworker`, вопрос — `Ask question to coworker`. В описании этих Tools в CrewAI сказано, что коллега ничего не знает о задаче и всё нужное надо передать в поручении.
- **`allow_delegation=True`** даёт агенту те же два Tool: `Delegate work to coworker` и `Ask question to coworker`. Документация CrewAI советует включать делегирование координаторам, а узким специалистам — выключать, иначе возможны петли делегирования (*Troubleshooting Collaboration*).
- **`max_iter`** — сколько шагов (вызовов LLM) агенту дано на одну задачу; после него агент обязан выдать лучший ответ, какой есть. По умолчанию в `crewai==1.15.22` — 25, в документации — 20. В курсе — `max_iter=5` с практики 1: страховка от «карусели».
- **`max_execution_time`** — ограничение времени задачи агента в секундах, по умолчанию не задано. В `crewai==1.15.22` агент по истечении времени не прерывается: CrewAI дожидается конца всей его работы (до `max_iter` шагов) и только потом выбрасывает `TimeoutError`, итог задачи при этом теряется. Реальный потолок времени — `max_iter`, а `max_execution_time` — порог, после которого человек получает сообщение вместо результата. Понятное сообщение человеку («не уложились, попробуйте позже») — забота кода запуска (Definition of Done, раздел 5).
- **Guardrail задачи** — `Task(guardrail=<функция>)`: функция получает итог задачи и возвращает «принято» или замечание; при замечании CrewAI повторяет задачу с ним, не больше `guardrail_max_retries` раз (по умолчанию 3). Это один из способов собрать цикл «генерация → линтер → исправление»; второй — Кодер сам вызывает `run_linter` в пределах `max_iter`. На практике 4 цикл собирается через Tool Кодера, guardrail — по желанию, после работающей Crew.

**Сколько стоит вызов LLM.** Запуск агента практики 3 — два вызова LLM (`search_docs` и финальный ответ) и около 2 минут на CPU, первый запуск после загрузки модели — до 10 минут. Для оценки Crew считайте 1–2 минуты на вызов: контекст растёт с каждым шагом, и поздние вызовы медленнее ранних. Путь Б: у бесплатных моделей OpenRouter — 50 запросов в сутки на аккаунт при покупке меньше 10 кредитов ([Limits](https://openrouter.ai/docs/api-reference/limits)); каждый вызов LLM — запрос. На машине с 8 ГБ памяти две модели для агентов вместе не помещаются (практика 3): одна модель на все агенты Crew плюс модель эмбеддингов для `search_docs`.
