# Мульти-агентная разработка приложений

> **Контекст:** Курс для 4 курса бакалавриата (108 часов). Интегрирован с курсом "Конфигурирование приложений". Студенты работают над одним выпускным проектом с двух сторон: инфраструктура (конфигурирование) + AI-слой (мульти-агенты).

---

##  Назначение

Устройство методического репозитория курса: структура и связи документов, педагогическая концепция, стек, правила разработки материалов.

---

## Модель веток

Репозиторий живёт в двух ветках, подключённых через `git worktree`:

| Ветка | Рабочая папка | Что содержит |
|---|---|---|
| `main` | `multi-agent-all/multi-agent/` | Материалы для студентов |
| `teacher` | `multi-agent-all/multi-agent-teacher/` | Всё из `main` + преподавательские материалы (`workshops-teacher/`, файлы `*-teacher*`) |

- В `main` файл `.gitignore` скрывает `*-teacher*` и `workshops-teacher/`; в `teacher` эти правила удалены.
- Общие документы правятся только в `main`, затем `git merge main` в рабочей папке `teacher`. Ветка `teacher` в `main` не мержится.
- Преподавательский файл создаётся только в `multi-agent-teacher/`: в рабочей папке `main` `.gitignore` его молча проигнорирует.
- Из студенческих документов нельзя ссылаться на `workshops-teacher/` — в `main` этих файлов нет.

## 🔗 Зависимости между документами

```
ROADMAP.md (что создавать следующим)
    ↓ (порядок производства материалов)
course-overview.md
    ↓ (определяет стек и философию)
syllabus.md
    ↓ (детализирует по неделям)
workshops/workshop-N.md ←→ workshops-teacher/workshopN/workshop-N-scenario.md
    ↓ (задания для студентов)        ↑ (методическое обоснование)
workshops/practice-N.md
    ↓ (требования к коду)
definition-of-done-ai.md
    ↓ (критерии оценки)
project-requirements-ai.md
```

**Правило:** При генерации нового материала (например, `workshop-2.md`) агент должен:
0. Прочитать `ROADMAP.md` → понять, какой артефакт следующий в очереди
1. Прочитать `syllabus.md` → понять место модуля в программе
2. Прочитать `course-overview.md` → соблюсти педагогические принципы
3. Прочитать предыдущий воркшоп → обеспечить преемственность
4. Прочитать `definition-of-done-ai.md` → убедиться, что задание ведёт к DoD

## 🧠 Педагогическая концепция (КРИТИЧНО для генерации материалов)

### Запрещено:
- ❌ "Говорящая голова" — лекции в формате монолога
- ❌ Live coding на лекциях (код только на практиках)
- ❌ Готовые ответы без процесса открытия
- ❌ Передача фактологии, которую можно найти в документации

### Обязательно:
- ✅ **Flipped Classroom:** теория вне аудитории, очное время — для применения
- ✅ **Problem-Based Learning:** каждая тема начинается с реальной проблемы
- ✅ **Project-Based Learning:** всё привязано к выпускному проекту
- ✅ **Конструктивизм:** студенты сами "изобретают" концепции через решение задач
- ✅ **Peer Review:** взаимная оценка кода и архитектурных решений

### Формат занятий:
- **Нечётная неделя:** Лекция-воркшоп (90 мин) — обсуждение, проектирование, презентации
- **Чётная неделя:** Практика (180 мин) — Pair Programming, код, интеграция

## 🛠️ Технологический стек

### Обязательные технологии:
- **Python 3.11–3.13 (CrewAI не поддерживает 3.14)** — основной язык
- **FastAPI** — фреймворк для API (из курса "Конфигурирование")
- **Ollama** — локальный запуск LLM (бесплатно, без API-ключей)
- **Qwen3:4b-instruct** — рекомендуемая локальная модель (2,5 ГБ, есть возможность tools). Альтернатива покрупнее — **Qwen2.5:7b**. ⚠️ Модель для агента обязана поддерживать function calling: у `qwen2.5-coder` возможности tools нет, Ollama отклоняет такие запросы с ошибкой `does not support tools`
- **Облачный OpenAI-совместимый провайдер** — OpenRouter (бесплатные модели, регистрация без карты) или Yandex AI Studio (оплата рублями); нужен для проверки переключения провайдеров
- **pydantic-settings** — управление конфигурацией через `.env`
- **pytest + unittest.mock** — тестирование с мокированием LLM
- **ChromaDB** — векторное хранилище для RAG (альтернатива: **pgvector**, если PostgreSQL уже поднят в курсе «Конфигурирование»)

### Фреймворки для мульти-агентов (выбор команды через ADR):
- CrewAI
- LangGraph
- LangChain
- Чистый Python (без фреймворка)

### Инфраструктура (из курса "Конфигурирование"):
- Docker + docker-compose
- PostgreSQL + SQLAlchemy/Tortoise ORM
- Alembic (миграции)
- GitHub Actions / GitLab CI (CI/CD пайплайн)
- VPS + reverse-proxy + HTTPS (деплой)

## 🎓 Выпускной проект

### Концепция:
Студенты строят **одно приложение** с двух сторон:
- **Курс "Конфигурирование":** инфраструктура, API, БД, деплой, CI/CD
- **Курс "Мульти-агенты":** AI-слой, который использует инфраструктуру через Tools

### Пример архитектуры:
```
┌─────────────────────────────────────────┐
│         Выпускное приложение            │
├─────────────────────┬───────────────────┤
│  Конфигурирование   │   Мульти-агенты   │
│  (FastAPI + БД)     │   (CrewAI/LangGraph)│
│                     │                   │
│  /api/tasks         │   Agent:          │
│  /api/users         │   - get_task_by_id│
│  /health            │   - search_tasks  │
│                     │   - check_syntax  │
│  Docker + CI/CD     │   ↓ вызывает      │
│                     │   /api/tasks      │
└────────────────────────────────────────┘
```

### Definition of Done (AI-часть):
1. ✅ 2+ агента с чёткими ролями
2. ✅ Кастомные Tools (включая code-analysis)
3. ✅ RAG для работы с документацией проекта
4. ✅ Мокирование LLM в тестах (CI/CD остаётся зелёным)
5. ✅ Переключение моделей через `pydantic-settings`
6. ✅ ADR с обоснованием выбора фреймворка

## ⚠️ Ограничения и предупреждения

1. **Бюджет на API:** Студенты работают в рамках бесплатных лимитов облачного провайдера (OpenRouter: бесплатные модели, 50 запросов в сутки). Локальная разработка через Ollama обязательна.

2. **CI/CD интеграция:** AI-тесты НЕ должны вызывать реальные LLM в CI/CD пайплайне. Только моки.

3. **Командная работа:** Все материалы рассчитаны на команды 3-4 человека. Индивидуальные задания не предусмотрены.

4. **Синхронизация с "Конфигурированием":** AI-часть должна использовать API, созданное в параллельном курсе. Нельзя создавать изолированные AI-компоненты.

5. **Оценивание 360°:** 50% преподаватель, 25% другие команды, 25% сокомандники (с коэффициентом вклада 0.5–1.2).

6. **Источник истины по темам — `syllabus.md`.** Если названия или номера циклов в `ROADMAP.md`, воркшопах или практиках расходятся с программой — прав `syllabus.md`, остальное нужно править.

7. **Векторная БД одна на курс:** ChromaDB по умолчанию, pgvector — как альтернатива для команд с уже поднятым PostgreSQL. Другие варианты (FAISS, Qdrant и т. п.) в материалах курса не используются.
